# 国家简报生成：单轮综合、局部修订与耗时诊断

## 2026-09-07 改动

国家简报仍使用配置中的 Dmall `gpt-5.6-luna`，不回退演示文本，不修改国家资料或证据，不改变客户作战包的九阶段流程。

1. **程序预加载完整证据**：首个模型请求已包含国家资料及全部三家企业资料，不再用四轮模型调用选择已知的读取工具。首轮不包含 `context.draft` 或 `market.managementDraft`，以免把演示结论当事实。
2. **精简管理层表达**：保留所有报告板块、三家公司、至少三条信号/风险/行动；减少段落重复，提示模型遵守既有字段长度和正式企业名称要求。没有放宽 schema 或证据校验。
3. **局部修订**：新增 `repair_country_brief`，参数为非空 `changes: [{field, value}]`。仅替换指定顶层字段，数组字段替换完整数组。按选中的字段 schema 校验其值，再对合并后的整篇结果执行完整结构及证据校验；未通过的草稿只存在本次内存中。拒绝未知/重复字段、空 changes、缺少初稿的修订和被输出长度上限截断的初稿。
4. **具体修订反馈**：同时反馈结构约束与可检测的语义问题；缺少企业名称时列出需要使用的正式名称。局部修订中的值按字段分别校验，避免复杂联合类型产生与当前字段无关的报错。未通过其他字段检查时仍保留已合法替换的字段。
5. **可观察性**：结果新增 `diagnostics`。服务日志记录模型轮次、可见 delta 首达时间、每轮耗时、token 使用和具体失败规则，不记录全文、思考内容或密钥。前端显示已用时和分析/撰写状态，不把无法估计的生成进度伪装成百分比。240 秒总时限保持不变，超时文案明确为生成超时。

## 配置

```dotenv
AGENT_PROVIDER=dmall-router
AGENT_MODEL=gpt-5.6-luna
COUNTRY_BRIEF_THINKING_EFFORT=low
```

国家简报思考档位优先级：`COUNTRY_BRIEF_THINKING_EFFORT` > `AGENT_THINKING_EFFORT` > `low`。客户作战包继续使用原来的 `AGENT_THINKING_EFFORT`（默认 `high`）。没有更换 URL 或 Key。

`diagnostics.modelTurns[].inputTokens/outputTokens/totalTokens` 是 provider 报告值；`thinkingChars` 仅是可见思考 delta 字符数，不是隐藏思考 token 数。统计中的模型轮次也不等于底层 HTTP 重试次数。

## 服务器实测（小样本，不是 SLA）

- 旧版加拿大：四轮读取约 28 秒，整篇生成约 151 秒，校验后整篇修订，240 秒超时失败。
- 首版单轮 + low、仍较长的文字：加拿大 136.9 秒成功。因此仅改思考档位/省掉读取轮次不足以保证快。
- 精简表达后加拿大两次：约 57.0 秒、61.4 秒，均一轮提交成功。
- 修订接口和提示完善后的巴西：约 65.5 秒，一轮提交成功，三家覆盖与证据/结构校验通过。
- 中间巴西样本发现标题不足 5 字、行动交付物不足 8 字、正式企业名称遗漏，以及空修订参数/联合 schema 报错不明确。对应问题均纳入提示和修订回归测试，不通过放宽校验解决。

以上是不同国家和少量样本，不能承诺所有任务固定一分钟。上游负载、输出长度和需要修订的次数仍会影响耗时；质量仍须人工复核，程序校验不等于已经核验每句事实。
