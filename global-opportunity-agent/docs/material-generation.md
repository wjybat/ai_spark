# 能力匹配与英文开发邮件的模型生成

## 运行方式

仍由同一个 pi-agent-core Agent 执行九个阶段。live 模式下：

1. 先取得市场、客户池、画像、商机、准入与证据链。
2. Agent 从上下文读取客户证据和系统提示中的 Dmall 能力目录，生成 `match_dmall_capabilities.analysis`。内容包括 1–4 项能力、独立参考分、差异化理由、建议验证范围、前置条件及不能承诺的事项。
3. 工具检查结构、能力 ID、引用归属、事实支撑和重复理由；固定规范名称，保留目录基础前置约束，按生成的参考分排序。live 路径不读取旧的固定评分矩阵。
4. 风险工具执行后，Agent 基于已接受的匹配和风险结果生成 `generate_research_brief.email`，包括英文主题、80–220 词正文、中文写作依据和事实引用。
5. 工具检查英文、长度、单行主题及事实引用，原样保留模型邮件；其他 Brief 字段继续由现有工具组装。前端分页、实时结果及工作包使用同一份已接受内容。

模型生成时，SSE 会显示对应阶段的生成提示。`generation` 由服务端记录来源、模型、推理强度和时间，不接受模型自行声明来源。demo 仍是规则/模板，并明确标注。

## 失败与边界

- 参数缺失、非法引用或格式错误会反馈给 Agent，在同一阶段修正；不会提前推进。
- 同一工具三次失败或总计达到 18 轮会终止；live 不使用模板兜底，不把不完整结果回填成成功。
- 校验保证结构和引用可追溯，不保证每句话的语义都真实。模型的需求、方案、收益与试点建议仍是假设，需要人工确认。
- 不新增客户事实，不联网采集，不发送邮件，不改变顶部纯前端扫描演示。

## 真实运行验证 · 2026-08-31

- 模型：现有 Dmall Router / `gpt-5.6-luna`，本地配置的 `xhigh`。
- 客户：Cencosud；范围：南美。
- 完整九阶段耗时约 116.6 秒，工具校验/执行失败 0 次。
- 模型选择：Open Platform 86、Data Cloud / 经营分析 83、OMS / 全渠道履约 79；不是原规则矩阵的 95/93/88 排名。
- 匹配理由分别围绕区域接口、经营指标治理、订单履约展开，包含不同的验证范围和观察指标。
- 邮件主题：`Cencosud: regional order and inventory data flows`。正文以 CencoDay 2026 的已核验平台战略开场，提出单一国家/流程的 API 与订单状态同步讨论；单独引用 `cencosud-cencoday-2026`，保留人工审核。
